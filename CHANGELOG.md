# Changelog

All notable changes to compodocx are documented in this file.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the version numbers follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

For the upstream compodoc history that predates the cngx fork, see <https://github.com/compodoc/compodoc/blob/master/CHANGELOG.md>.

## [Unreleased]

### Added

- **Stable identity for additional pages.** Nodes in `summary.json` take optional `slug`, `label`, `title`, `heading` and `aliases`, so a page keeps its URL when its wording changes: the slug fixes the URL, the label is the sidebar text, the title is the page title, `heading` renders the title as an `<h1>`, and an alias keeps an old URL working through a redirect page and a `redirects.json` entry. New `--includesLabels` flag and `includesLabels` config key read labels and titles per slug from a JSON file. Invalid slugs and aliases stop the build with the position in `summary.json`. See [docs/additional-pages.md](docs/additional-pages.md).
- **Hook tokens.** A property a component only reads (`color: var(--badge-color, var(--accent))`) can now be documented with `@cssprop {<syntax>} [--name=default] - description`, or its alias `@cssproperty`, the form the custom-elements-manifest uses. The block never attaches to the declaration below it, several lines in one block give one hook each, and `@cssprop` lines also work inside an `@overview` block. Hooks show on the Theming tab and the style page with a "Hook" badge (translated in all 17 locales) and carry `kind: 'css-hook'` in the JSON export (schema stays 6); the llm-md export lists them like any other token.
- **Notice for doc blocks that attach to nothing.** A style doc block with token tags (`@type`, `@default`, `@group`, `@example`, `@since`, `@deprecated`, `@see`, `@relatedTo`) that sits above no property is reported once per run as `Style comments: <n> doc blocks not attached` with `file:line`. The build still exits with code 0. Prose-only blocks, file-level blocks and the block above a private mixin are not reported.
- **Notice for a hook that its own sheet declares.** `Style comments: <n> hook tokens also declared in their sheets, declaration kept`.

### Changed

- **Two additional pages with the same path stop the build.** One no longer silently overwrites the other; the error names both nodes and files. Give one of them a `slug`.
- **A sidebar group that gets a slug loses its remembered open/closed state once.** The stored state is keyed by the group id, which is now the slug path.
- **Links to a renamed page are also fixed when they are relative.** A Markdown link such as `e0003-old-name.html` on a page in the same folder now points to the new page.
- **A token documented in several sheets of one component is listed once.** The Theming tab, the style pages and the JSON export merge same-name tokens: `@property` beats a plain declaration, which beats a hook; description, group and the other fields come from the first sheet that has them.

### Fixed

- **Nested additional pages are written to the right folder.** A page whose slug is a prefix of an ancestor's slug (a child `guide` below `guide-basics`) was written to a wrong folder.
- **Malformed `summary.json` entries no longer crash or hang the build.** Entries with a non-string `title` or `file`, children of a node with neither `title` nor `slug`, a non-array `children`, `null` entries, objects under keys other than `children` and pages deeper than five levels with a missing file are skipped.
- **Repeated token names no longer repeat the row id on the Theming tab.**
- **A `@cssprop` tag is no longer reported as an unknown tag.**

## [0.9.1] - 2026-10-21

### Fixed

- **`customFavicon` is now the icon the pages link to.** The file was copied to `images/favicon.ico` while every page kept linking the bundled `images/favicon.svg`. It is now copied as `images/favicon.<ext>` (`.svg`, `.ico` and `.png` keep their type) and linked with the matching `type`; the bundled icon is linked only without `customFavicon`.
- **`customLogo` shows in the sidebar again.** The image source was built from the configured path (`images/./brand/logo.svg`) instead of the copied file name (`images/logo.svg`).
- **No more read errors for missing optional root files.** Every run logged `Error during <cwd>/TODO read` (and the same for a missing `CHANGELOG`, `CONTRIBUTING` or `LICENSE`) as if something had failed. Missing optional files are now skipped quietly; a missing `README.md` still gets its one `Continuing without README.md file` notice, and a file that exists but cannot be read is still reported.

## [0.9.0] - 2026-10-19

Upgrading from 0.8: this release documents Angular 21+ standalone code only, moves every symbol page into the folder of its feature (old URLs are mapped in `redirects.json`), makes the feature sidebar the default and writes the JSON export with schema 6. Removed flags, config keys and template overrides are ignored with a warning instead of failing the build. Update the package, run it once and work through the warnings; [MIGRATION.md](MIGRATION.md) explains each change.

### Added

- **Angular 22.** Projects on Angular 21 and 22 are both documented; Angular 21 output is unchanged.
  - Classes decorated with `@Service` from `@angular/core` get their own kind: a page with a Service badge and the `autoProvided` and `factory` options, the services section of their feature, a Services chapter under `menuLayout: 'type'` (`toggleMenuItems` accepts `services`), coverage rows, search and palette labels and a services card on the overview. The decorator is recognised by its import, so a project decorator called `Service` keeps its class a plain class. New template override `service`.
  - The JSON export gains an optional top-level `services` list; the llm-md export lists services with the injectables, and `compodocx diff` reports `service-added`, `service-removed` and `service-changed`.
  - Members initialised with `httpResource` (from `@angular/common/http`) or `injectAsync` (from `@angular/core`) get their own member kind and badge; `injectAsync` counts as an API that needs an injection context.
  - On a project that declares Angular 22 or later in its `package.json` (`dependencies`, then `peerDependencies`, then `devDependencies`), a component without a `changeDetection` option shows the OnPush badge and the value `OnPush (default)`.
  - The Angular API list links the 76 APIs angular.dev lists for Angular 22, such as `Service`, `injectAsync` and `withXhr`. Entries angular.dev no longer lists stay, so links to deprecated and removed APIs keep working.
  - `@playground` projects for Angular 22 without a declared TypeScript version get TypeScript 6.0.
- **Semantic facts in the JSON export.** compodocx now analyses the whole project through the `-p` tsconfig (`extends`, `paths` and `baseUrl` included) and adds optional fields to every symbol in `documentation.json`: the entry point that exports it (`entryPoint`, `exportedBy`), whether an exported symbol is reachable from no entry point (`notExported`), who uses it (`usedBy`), its dependency injection role (`di`: provider or feature function, feature type, tokens provided and read, whether it needs an injection context) and, for injection tokens, the shape of the token type (`token`). A top-level `semantic` object lists the entry points (`ng-package.json` entry files and barrel-shaped tsconfig `paths` targets) and the counts, which the build log prints as one `Semantic analysis:` line. A `provide:` entry inside a function the provider calls directly counts towards its `di.providesTokens`, and `export const Foo` and `export type Foo` in one file keep separate facts. Symbols without facts are written as before; every new field is optional. See the export section in [docs/configuration.md](docs/configuration.md).
- **Dependency Injection chapter.** Providers, feature functions and injection tokens have their own sidebar chapter and a landing page, `dependency-injection.html`. A provider that accepts a feature type (`provideFoo(...features: FooFeature[])`) shares one page with every other provider and feature function of that type: the page of the feature type shows the type definition, then one section per provider and per feature function (signature, description, badges, provided tokens), the tokens the providers provide and a combined "Used by" list. Each section has the anchor `<FeatureType>--<name>`. A provider without a feature type gets its own page. Links to a provider, a feature function or the feature type itself land on these pages.
- **Token pages show where a token comes from.** A token page now shows the shape of its type (interface, signal, function, primitive, union or other), the default from the `factory` option of `new InjectionToken(...)`, the providers that provide it and the symbols that inject it. The JSON export gains the optional `tokens[].factory` field.
- **Utilities chapter with one page per symbol.** Every function, constant, type alias and enumeration gets its own page. The Utilities chapter and its landing page, `utilities.html`, list them in four groups. Overloads share one page.
- **"Used by" from the project analysis.** Symbol pages list the declarations that use the symbol, taken from the semantic analysis instead of a text search for the name.
- **Injection context badge.** Functions and constants that call `inject()` or another API needing an injection context, directly or through one called function, carry an "Injection context" badge on their page, in the Utilities list and on provider pages. Provider and feature function badges come from the same analysis.
- **Functional resolvers and function guards as their own kinds.** A `ResolveFn` constant gets its own page and a Resolvers chapter; guards and interceptors declared as functions are listed with the other guards and interceptors. Only `ResolveFn` marks a functional resolver (a function typed with the class interface `Resolve<T>` is not one). The JSON export keeps them under `miscellaneous` with `functionalKind`.
- **Provider calls in `providers` arrays are links.** `providers: [provideFoo(withMode('wide'))]` on a component or directive renders as `provideFoo(withMode(…))` with both names linked. The JSON export adds an optional `call: { callee, args }` to such `providers` / `viewProviders` entries; `name` and `type` are unchanged.
- **One search result per provider and feature function.** Search lists every provider and feature function of a feature type page as its own result, linking to its section.
- **Undocumented exports are listed in the build log.** Symbols that are exported from their file but reach no entry point get no page, no menu entry and no row in the coverage report; links to them render as code. The build prints them once, with file and line, after the `Semantic analysis:` line.
- **llm-md export.** A "Public tokens" section follows "Public functions", and symbols that reach no entry point are left out of every section.
- **Features derived from the code.** Every documented symbol belongs to a feature: its entry point, then a feature key below it. The key comes from the `features` config (file globs), an `@feature <key>` tag, the imports between the folders of an entry point (folders that import each other form one feature; a folder imported by half of the others makes the whole entry point one feature), or, in apps, the first folder below `src/app` (descending into `features`, `pages` and `domains`, see `featureContainers`). Files in role folders such as `di/`, `routes/` or `components/` join the feature their file name starts with (`featureRoleFolders`). The build log prints one `Features:` line with the detector counts. See "Features" in docs/configuration.md.
- **Feature pages.** Each feature has a page, `index.html` in its folder, with the import path, the README of the feature folder, the features of an entry point, its members by role, links to their Theming tabs, and the features of other entry points it builds on or that extend it. New template override `feature`.
- **Features in the JSON export.** Each symbol entry can carry `feature: { entryPoint, key }`, and `semantic.features` lists every feature with its detector, README path, `buildsOn` and `extendedBy`.
- **`compodocx migrate jsdoc <dir>`** removes `@category` and `@docsKind` tags from `.ts` sources (`--dry-run`, `--json`). Only the tag line is removed; the text below it stays.
- **Classification axes.** A new config key, `classificationAxes`, declares axes such as stability or atomic-design level with their allowed values. A symbol gets its value from an `@axis <name> <value>` tag, a file glob or the axis default; `kinds` limits an axis to some symbol kinds. Symbol pages show one chip per value, the search palette offers one facet per axis, the JSON export adds `axes` per symbol and `semantic.axes` with counts, and llm-md prints an `Axes:` line. Axes never change URLs, features or the sidebar. Invalid values and tags are reported in the build log, followed by one `Axes:` summary line. See "Classification axes" in docs/configuration.md.
- **Search facets `feature` and `entryPoint`.** The search palette shows the feature of a result.
- **Redirect map.** Each version's output holds `redirects.json` (`{ "schemaVersion": 1, "redirects": { "<old path>": "<new path>" } }`) with every page path of earlier layouts: kind folders (`components/X.html`, `functions/x.html`, `providers/X.html`, ...) including their `-1`, `-2` names, `miscellaneous/` pages and collection anchors, and `features/` and `categories/` pages. The version switcher follows it, also into versions built before the map existed. Links written by hand in README or additional-page markdown that still point at an old page are pointed at its new place.
- **Free-standing style files (`styleFiles`).** The new config-only key `styleFiles` takes globs of `.css` / `.scss` files relative to the config file's folder (the `-p` tsconfig folder without a config file), for example `["projects/*/theming/**/*.css", "projects/themes/**/*.{css,scss}"]`. `node_modules`, `dist`, `.git` and the output folder are never matched, other file types warn once, and a file a component already reads through `styleUrl` / `styleUrls` stays on that component's Theming tab. A matched file is documented when it has an `@overview`, a documented token (description, `@type` or `@group`) or a documented SCSS mixin or function; the build log prints `Style files: <n> (<p> pages, <k> linked to <s> symbols, <l> without documented content)` and names the files without documented content. Style files are placed into features like symbols, and a folder holding only style files can become a feature of its own. See "Style files" in docs/configuration.md and docs/theming-tokens-authoring-guide.md.
- **`@themes` and a Theming tab for directives.** A file-level `@themes Name[, Name...]` tag (in the `@overview` block or a block of its own) links a style file to the components and directives it themes, resolved like `{@link}` names. The file's tokens, overview and source join each target's Theming tab, which names the linked files. Directives get a Theming tab too. A name that is not found, is another kind or is ambiguous logs one warning per file, and so does `@themes` on a file without documented content, naming the ignored targets. `@themes` is the only link besides a component's own `styleUrl`; there is no matching by selector, token name or file name.
- **Style pages.** A style file that themes no symbol, themes two or more, or has documented mixins (while `themingTabSections` shows `mixins`) gets a page, `<file name>.html` in its feature folder (`stylesheets/` without project analysis facts), with the file name, a CSS/SCSS badge, the entry point and feature breadcrumb, an import line (from the nearest `package.json` `exports` entry that maps the file, `@use` for SCSS and `@import` for CSS), the overview, the symbols it themes, its tokens, mixins and source. The feature layout lists style pages below a feature's primary members, the type layout gets a "Style files" chapter (`toggleMenuItems` accepts `styles`), `references.html` lists them under their feature, and search shows them as kind "Style". New template override `style`.
- **Design tokens page.** `design-tokens.html` lists the documented tokens of every style file that themes no symbol, grouped by `@group`, with name, type, default, description and the defining file. Token anchors are `token-<name>`, group anchors `group-<slug>`; a name defined again in a later file gets `-2` and a warning. The page is generated only when such tokens exist and is linked from the Features chapter, the Style files chapter, `references.html` and the feature pages. New template override `design-tokens`.
- **Theming section on feature pages.** A feature page lists the feature's style pages (first sentence of the overview, token and mixin counts), its components and directives that have a Theming tab, and the design tokens page when one of the feature's style files feeds it.
- **Documented SCSS mixins and functions.** A `///` block directly above `@mixin name(...)` or `@function name(...)` documents it: parameters from the signature, `@param` lines in SassDoc (`@param {Type} $name [default] - text`) or plain form, `@content`, `@return` and `@example`. They show in a "Mixins" section on the Theming tab and on the style page; private names (`_x`, `-x`) and undocumented mixins stay hidden. New `themingTabSections` value `mixins` and block override `block-theming-mixin`.
- **`@relatedTo` in style comments.** On a token, `@relatedTo Name[, Name]` renders a "Related" row of links (names that resolve to nothing render as code); at file level it renders a Related section on the style page. The `block-theming-token` override receives the resolved names as `related`.
- **Style files in the exports.** The JSON export gains an optional top-level `styleFiles` list (file, language, overview, tokens, mixins, themes, relatedTo, feature) for files with documented content, whose sources join `styleSources`. Directives gain `themeTokens`, `themeOverview` and `themeStyleSources` when a file themes them, and a component's theme fields include its linked files. Tokens carry `relatedTo` when set, and `semantic.features` can list features that only style files fall into. Every new field is optional. `compodocx diff` compares directive `themeTokens` like component ones but does not compare `styleFiles`. The llm-md export lists "Theme tokens" on directives and adds a "Design tokens" section with the unlinked tokens by group and the mixins of each file.
- **Typed route model.** compodocx reads routes through the project analysis instead of a text parser. A router starts at `bootstrapApplication(<component>, <config>)` (anywhere in the documented files, also inside an `if` or a function): the config is an object, a named config (across files) or `mergeApplicationConfig(...)`, and every `provideRouter(routes, ...features)` in its `providers` (arrays, spreads, named arrays) is one router. Route arrays are recognised by their type from `@angular/router` (`Routes`, `Route[]`, `Array<Route>`, `satisfies Routes`, `as Route[]`, aliased and namespace imports), never by name. Spreads and `children` are followed, and `loadChildren` route arrays (`() => import(...).then(m => m.X)`, `.then(({ X }) => X)`, `async () => (await import(...)).X`, `() => import(...)` for a default export) are expanded below their route; `loadComponent` targets link to the component. Every route field is kept: `path`, `pathMatch`, `matcher`, `outlet`, `component`, `redirectTo` (string or function), `title` (string or resolver), the five guard lists, `resolve`, `providers`, `data`, `runGuardsAndResolvers`. Values the type checker can evaluate (string literals, consts, enum members, templates of those) are shown as text, anything else as its source; guard and provider calls keep their source with the callee linked. Exported route arrays no router mounts are listed as unmounted routes. The build log prints `Routes: <n> in <r> routers, <u> unmounted (<l> lazy, <d> dynamic values)`.
- **Routes page.** `routes.html` is a table per router and per unmounted route array: full path (own segment emphasised, indented by depth), target (linked, lazy badge, external package specifier, redirect), guards, resolvers, title, providers and `data`; empty columns are left out. Each section shows the bootstrap, the config, the route array and the router features. Rows and sections have stable anchors (`route-<n>-...`). The page needs no script. Template override `routes` receives `routing`, `symbols` and `depth`.
- **Routed at / Mounted at.** Component pages list the routes they are rendered at, route array variables the places they are mounted at (or link their unmounted section), each linking its row on the routes page. New block override `block-routed-at`. Feature pages gain a Routes section listing the routes of their members.
- **Routes in search.** The command palette finds routes by their full path (also without the search index) and opens their row; the routes page has search sub-results per router section.
- **Routes in the exports.** See "JSON export schema 6" under Changed. The llm-md export gains a "Routes" section: one block per router or unmounted route array, the routes as nested list items with target, guards, resolvers, title, providers, `pathMatch`, `matcher` and `runGuardsAndResolvers` (not `data`).
- **`--disableRoutes` / `disableRoutes`.** Turns route reading off: no routes page, menu entry, backlinks, palette entries or exported routes. `--minimal` turns it on too.
- **Role groups in the feature sidebar.** Under `menuLayout: 'feature'`, a feature with primary members (components, directives, pipes, injectables, classes, guards, interceptors, resolvers, entities) lists them and its style pages at the top and puts the other members into collapsed nodes: **Configuration** (tokens, providers, feature functions and feature types, each provider cluster folded into one entry) and **More**, with one labelled group each for utilities, constants, types and other classes. Empty nodes are left out. A feature without primary members keeps its flat list. Tokens therefore move from the top level into Configuration.
- **`menuFeatureSections`.** A config-only key chooses per role where it shows in the sidebar: `own` (a node of its own), `more` (inside More), `top` (flat at the top) or `hidden` (not in the sidebar, still on the feature page, in the API reference and in search). The default is `{ "configuration": "own", "utilities": "more", "constants": "more", "types": "more" }`; an unknown role or value is ignored with a warning. See "Sidebar Grouping" in docs/configuration.md.
- **Section jump bar on feature pages.** Below the header, a feature page links each of its non-empty sections (features, member roles, theming) with the number of entries.
- **`di.configAccessor` in the JSON export.** A function that returns a value read from a token its library configures through a provider with features is marked with `di.configAccessor: true`. The field is optional.

### Changed

- **TypeScript 6.0 parser.** compodocx reads sources with TypeScript 6.0 (ts-morph 28). tsconfig options that TypeScript 6 deprecates (`baseUrl`, `moduleResolution: node`, `target: ES5` and others) are still read, and the project analysis keeps its results for such projects.
- **The sidebar and the entity index are shared files.** Each page used to carry the whole sidebar menu and the command palette's entity index inline. They are now written once per site (per version folder in multi-version output) to `js/menu.js` and `js/entities.js` and loaded by every page with a content hash in the `?v=` query, so a redeploy never serves a stale copy. Page URLs, anchors and search results are unchanged; pages get much smaller (on a large library the output shrank from about 2.4 GB to about 54 MB). Pages have no sidebar menu when JavaScript is off.
- **A `menu` template override is rendered once for all pages.** It receives the root data (`depth` `0`, `context` `'menu'`) instead of the data of each page. See [MIGRATION.md](MIGRATION.md).
- **Angular 21+ standalone code only (breaking).** NgModules, decorator members, constructor injection in Angular classes and class guards/interceptors/resolvers are no longer documented; class guards and interceptors show up as plain classes or injectables. A full run warns with the number of legacy constructs it skipped (NgModules, `@Input`/`@Output`/`@HostBinding`/`@HostListener` members, constructor injection, class guards/interceptors/resolvers, `standalone: false`, `RouterModule.forRoot/forChild`, string `loadChildren` and similar) and lists their locations per kind; the exit code is unchanged. See [MIGRATION.md](MIGRATION.md).
- **JSON export schema 6 (breaking for export consumers).** `schemaVersion` is 6 (0.8 wrote 2). Removed: the top-level `modules`, `entryComponents` on components, `category` and `docsKind` on every entry and member, `referencedBy` (use `usedBy`) and `factoryKind` on function entries, which was guessed from the name prefix (use `di.role`, `di.featureType` and `di.usesInjectionContext`). Reshaped: `routes` is a list of typed route roots, `{ kind: 'router' | 'unmounted', bootstraps?, config?, features?, array?, routes }`, each route `{ path, fullPath, component?, loadChildren?, redirectTo?, title?, canActivate?, ..., file, line, children? }` with references as `{ name, file?, source, call? }`, written only when there are routes; component style sources move into a shared top-level `styleSources` map, `themeStyleSources` lists keys into it and inline styles get a per-component key (`<component file>#inline-<n>`) instead of a shared `<inline-style-N>`; `inputsClass`, `outputsClass`, `hostBindings` and `hostListeners` come from signal APIs and the `host` object only, `guards` and `interceptors` list functional ones only; `ExportComponent.themeOverview` is typed as a string (it was declared `string[]`). Values: the `defaultValue` of a signal input or model is the initial value argument only, without the options object (`output({ ... })` has none), a string `alias` option is written as the new optional `alias` field, and `type` is the first type argument (`input<boolean | undefined, unknown>()` gives `boolean | undefined`); `providedIn`, generic type arguments, top-level parameter types and theme `file` paths change as listed under Fixed. Components gain the optional `routedAt` and route array variables `mountedAt`. `compodocx diff` accepts schema 6 only (an older export exits with code 2 and the re-export message) and does not compare routes, so stored exports must be re-exported. See MIGRATION.md.
- **Standalone imports link without module pages.** The overview always shows the standalone dependency graph. On component pages, imports link to documented components, directives and pipes, Angular API symbols link to angular.dev, anything else stays plain text.
- **The routes page and its menu entry appear only when there are routes.** Projects without routes no longer get an empty `routes.html`.
- **Route files are documented as written.** Variables declared in a file with a `Routes` array used to show rewritten default values (lazy imports turned into strings, spreads inlined); they now show their source. An exported route array the old parser could not read is now documented like any other variable.
- **Utilities and Dependency Injection replace Miscellaneous (breaking).** The Miscellaneous chapter, its four collection pages and the `miscellaneous/` folder are gone; symbol pages get pages of their own, and the page of a feature type replaces its interface or type alias page; `redirects.json` maps the old pages. The page overrides `miscellaneous-*` are renamed to `utilities`, `function`, `variable`, `typealias` and `enumeration`. MIGRATION.md lists every moved URL and renamed override.
- **Badges from the analysis.** Provider, Feature and Injection context badges come from the project analysis; the badges guessed from name prefixes (`provideX`, `withX`, `injectX`, `createX`) are gone, and so is `factoryKind` in the JSON export (see "JSON export schema 6").
- **Documentation coverage counts documented symbols only.** Symbols that reach no entry point are left out of the coverage report, its JSON and the coverage threshold.
- **The feature layout is the default (breaking).** `menuLayout` defaults to `'feature'`: one Features chapter with the entry points as a tree of their import path, each feature below its entry point and the primary members of each feature below it, plus the `references.html` portal. Set `menuLayout: 'type'` for one chapter per kind; its chapters are grouped by feature too.
- **Breadcrumbs, references and search from features.** Symbol pages show entry point and feature in their breadcrumb in both layouts, `references.html` has one section per feature, and pages carry `feature` / `entryPoint` search facets instead of `bucket` / `tier`.
- **Page URLs grouped by entry point and feature (breaking).** Every symbol page lives in the folder of its feature: the entry point's import path without a scope all entry points share, then the feature key (`forms/select/SelectPanel.html`, `app/AppComponent.html`). A feature page is `index.html` in that folder, the page of a feature type with its providers takes the feature type's place, and kind folders such as `components/` are gone (they remain only when the project analysis has no facts). File names are safe for every file system: characters outside `A-Z a-z 0-9 . _ -` become `-` (`Unnamed function` is `Unnamed-function.html`), and names that clash ignoring case keep the bare name for one symbol and get `-<kind>` or `-2`, `-3` for the others. Links to a same-name copy now reach its own page. See MIGRATION.md.
- **Type-link helpers take the page depth (breaking for custom templates).** `helpers.linkTypeHtml(type, { depth })` and `helpers.functionSignature(method, depth)` need the depth of the page they render on (`data.depth`), since pages sit at different depths. See docs/custom-templates.md.
- **Watch rebuilds see edited imports.** Decorator values and templates read from an imported file were cached for the whole process, so a watch rebuild kept the old value after that file changed. Each run now reads them fresh.
- **One generation pipeline.** Every run (one-shot build, coverage test, watch rebuilds) now goes through a single sequence of phases with one table of prepare steps, instead of two hand-maintained queues and a callback chain. The generated output is byte-identical to before; CLI flags, defaults and the export schema are unchanged.
- **Programmatic entry point is `runCompodocx` (breaking for API users).** The `Application` and `CliApplication` exports are removed. `runCompodocx` is exported as experimental; the CLI remains the supported entry point. See [MIGRATION.md](MIGRATION.md).
- **The "done" log line waits for every file.** The `--assetsFolder` copy is now awaited, so `Documentation generated in ...` appears only once all files are on disk. The seconds in that line count from the start of the generation run instead of process start.
- **Unknown tags in style comments are reported, not kept.** A tag the style comment parser does not read (including tags other than `@themes` and `@relatedTo` inside an `@overview` block) is no longer appended to the token description. It is dropped, and the build logs one notice per run, `Style comments: <n> unknown tags ignored (@todo x1, ...)`, followed by one `file:line @tag` line per occurrence. The exit code is unchanged. See MIGRATION.md.
- **`themingTabSections` default gains `mixins`.** The default list is `overview`, `index`, `tokens`, `mixins`, `source`. A project that sets the list explicitly must add `mixins` to see documented mixins.

- **Anchors of private members.** A member named `#clicked` got `id="#clicked"` and links to `##clicked`, which never matched. Member anchors are now valid ids (`clicked`).
- **Injected fields with a type argument.** A class field initialised with `inject<T>(X)` (for example `inject<TemplateRef<Ctx>>(TemplateRef)`) was not recognised as injected, so it showed no `inject()` badge, an `unknown` type and no entry in the Dependencies section. `inject()` is now detected from the syntax tree, including type arguments, chained calls and aliased or namespace imports of `inject`.
- **Signal inputs, outputs and models.** They were recognised by matching the text of the default value, so a string default that mentioned `input`, `output` or `model` (for example `'<code>input</code> ...'`) was listed as an input, and a long string of that shape could stop the build. A property is now a signal input, output or model only when it calls `input`, `input.required`, `output`, `model` or `model.required` imported from `@angular/core` (named, aliased or through a namespace). Members with nested generic types (`input<Foo<Bar> | undefined>()`) or without a type argument (`input.required()`) now get their kind badge and count towards the signal adoption figure on the overview page, and members the text match missed (a function type argument, an `output` with options) are listed as inputs or outputs.

Services provided in `'root'` or `'platform'` now show as singleton services. String values are stored without quotes for both services and injection tokens (tokens previously kept the source quotes, e.g. `"'root'"` in the JSON export); pages still render the literal in single quotes.
- **`HttpContextToken` on token pages.** Tokens created with `new HttpContextToken(...)` were rendered as `InjectionToken<T>` on the token page and in the llm-md export. The constructor is now kept in the new optional `tokenClass` export field and shown as `HttpContextToken<T>`.
- **No local machine paths in theme data.** Theme style sources and theme tokens stored the absolute path of each style file, which leaked into the JSON export and made it differ between machines. Their `file` values are now relative to the working directory with forward slashes, like every other entity's `file`.
- **Stable output between runs.** Source files were crawled in the order the file scanner returned them, which varies between runs. Symbols sharing a name could swap order, and duplicate-name suffixes (`Todo-1`, `Todo-2`) could point at a different declaration on each build. Files are now crawled in sorted path order.
- **Links on the app-config page.** Links from the app-config page to documented provider functions pointed one directory above the docs root and were broken. They now resolve from the page's own location.
- **Unresolved `{@link}` targets.** A `{@link Name}` whose target is not a documented symbol rendered as a link to a file named after the symbol, which does not exist. It now renders as inline code, like an unresolved type reference. URLs and file targets are still links.
- **Generic type arguments.** Types with more than one type argument were written with `|` between the arguments, for example `Record<string | number>` for `Record<string, number>` or `Pick<Options | key>`, in the HTML, the JSON export and the llm-md export. The arguments are now separated by commas. `compodocx diff` between an export from before and after this fix reports these type strings as member changes.
- **Variable initializers and enum values are escaped.** A default value such as `new Map<string, number>()` was written into the page as raw HTML, so the browser dropped everything between `<` and `>`. Variable initializers and enum member values are now escaped and shown as written.
- **Rest parameters with a documented type.** A rest parameter whose type links to a documented symbol lost its `...` in function signatures (`provideFeature(features: Feature[])`). The marker is kept now.
- **Links in JSDoc tags.** Labelled links in tag comments (`{@link Foo|label}`, `{@link Foo label}`, `[label]{@link Foo}`, `{@link https://... label}`) were reordered or cut at the URL scheme and rendered with a broken relative `href`; `{@linkcode}` and `{@linkplain}` were dropped. Tag comments keep links as written and every link is resolved when the page is rendered, through the same lookup as descriptions. `@returns` of functions, accessors and host listeners now resolve their links too (they were printed raw), and a link target that is neither a documented symbol, a URL nor a `.md`/`.html` file renders as code instead of a broken link.
- **Links in custom tags.** `@slot`, `@since`, `@group` and the other single-line tags lost the text of an inline link (`@since {@link Foo} 1.0` gave `1.0`); `@relatedTo {@link Foo}` resolves to `Foo`, and slot descriptions render their links.
- **Constructor `@param` with a link.** A `{@link}` in the `@param` of a constructor parameter property crashed the HTML build (`result.replace is not a function`) and wrote syntax-tree objects into the JSON `description`.
- **Decorator values imported through a re-export.** A value found through `export * from` in the imported file was dropped.
- **`--publicApiOnly` keeps symbols re-exported through a barrel.** A symbol re-exported from an `index.ts` or `public-api.ts` barrel was dropped when its name was found in the barrel instead of the declaring file: a name in a `*.api.md` report whose first text match was the barrel, `import { x }` followed by `export { x }`, a named re-export through a nested barrel, `export { a as b }` and `export * from './x.js'` in `index.d.ts` files. compodocx now follows each public name through the barrels to its declaration. `export * from './folder'` in an `index.d.ts` file no longer stops the build with `EISDIR`. An alias listed in a `*.api.md` report is still not followed.
- **The config schema ships with the package.** `src/config/schema.json` was not in the npm package, so `"$schema": "./node_modules/@cngxjs/compodocx/src/config/schema.json"` in a config file resolved to nothing. The file is published now.
- **A custom or named theme stays in place.** The script that restores a theme chosen in the theme picker ran on every site, also when a custom or named theme hides the picker. A choice stored by another compodocx site on the same origin replaced the configured stylesheet. The script now ships only with the picker.
- **`--publicApiOnly` on Windows and in folders with glob characters.** The search for `index.d.ts` files, `*.api.md` reports and the declaring source files found nothing on Windows or below a folder whose name contains characters such as `(`, so every symbol was documented. These files are found now.
- **Coverage thresholds from the config file.** A number in `coverageTest` or `coverageMinimumPerFile` was ignored and the default threshold applied, and `coverageTestThresholdFail: false` was overridden by the flag's default. A number is now the threshold, `true` uses the default (70 / 0), and the config value of `coverageTestThresholdFail` applies unless the flag is given on the command line.
- **`ng add` script rewrite.** The schematic replaced every `compodoc` word in existing scripts with the script prefix: a custom `--script-prefix` produced calls such as `docs -p ...`, and arguments such as `-d docs/compodoc` were rewritten too. Only the binary in command position (start of the script, after `&&`, `;`, `|` or `npx`, also as a path) is rewritten now, always to `compodocx`. Newly written scripts call `compodocx` too; the prefix only names the script keys.
- **`TODO.md` is rendered.** A project `TODO.md` got a page and a menu entry, but the page was empty. It now renders like the other root markdown pages, and the `markdown.js` template override applies to it.
- **Watch mode keeps the other root pages when a markdown file is missing.** Rebuilding the root markdown pages removed the last queued page for every one of README, CHANGELOG, CONTRIBUTING, LICENSE and TODO that the project does not have. Only the root markdown pages are removed now.
- **`{@link}` in theming comments.** Token descriptions, `@deprecated` notes, mixin descriptions and `@overview` text on the Theming tab, on style file pages and on `design-tokens.html` showed `{@link ...}` as written. `{@link --token}` now links to the token's row on the same page (code when the page has no such row), and other targets resolve like `{@link}` in any description.

## [0.7.1] - 2026-06-16

A `playgroundVendor` payload-size fix. Vendoring a real component library now produces a slim StackBlitz project that launches instead of failing with `413 Request Entity Too Large`.

### Fixed

- **`playgroundVendor` payload now fits StackBlitz's project-POST limit.** Vendoring a real component library previously embedded the whole `dist/<pkg>` tree verbatim, which blows StackBlitz's ~2 MB `openProject` POST limit and fails the playground launch with `413 Request Entity Too Large`. The vendored payload is now slimmed and pruned: sourcemaps (`*.map`) and legacy or duplicate bundle directories (`esm2022/`, `esm2020/`, `fesm2020/`, ...) are dropped - keeping only `fesm2022/*.mjs`, typings, and the `package.json` files - and each package is reduced to the entry points the playground actually imports, plus any sibling or cross-package entry point a kept FESM chunk or its typings references, followed transitively. SCSS-only dependencies referenced via `@use` now seed the vendor closure as well, so a theme bridge is vendored from the local build instead of resolving stale from the registry. Pruning is conservative: a package with no `exports` map, or whose imported subpath maps to no known entry point, still ships whole.

### Added

- **`playgroundVendorCap` and `playgroundVendorIncludeSourcemaps` config keys.** `playgroundVendorCap` (default ~1.5 MB, set under the StackBlitz POST limit) is the backstop byte cap on a single playground's slimmed-and-pruned vendored closure; a closure that exceeds it fails the build naming the per-package bytes, and says so explicitly when the payload also exceeds the StackBlitz limit. `playgroundVendorIncludeSourcemaps` (default `false`) keeps `*.map` sourcemaps in vendored packages.

## [0.7.0] - 2026-06-15

A playground-focused release. The `@playground` (StackBlitz) engine gains local-build vendoring, a pre-publish compile guard plus a standalone validate command, a customizable page shell, application-config injection, and configurable dependency-walk caps. All additions are config-only or opt-in; existing playgrounds render unchanged.

### Added

- **Vendoring the local build (`playgroundVendor` / `playgroundVendorRoot`).** Names and/or globs (`"@cngx/*"`) of locally built packages to embed into `@playground` projects from `dist/` instead of pulling them from the npm registry. When a playground imports a matching package, its whole built directory plus the transitive closure of other matching packages is embedded in the manifest and wired as a `file:` dependency, so the playground runs against the working tree rather than the last published release. `playgroundVendorRoot` (default `dist`) sets the base directory the closure is read from; each package is located by its `package.json` `name`, anywhere under that root. Registry peers (`@angular/*`, `rxjs`, `tslib`, ...) stay registry dependencies. Naming a package whose build output is missing fails the docs build with a clear message; a glob that matches nothing only warns.
- **Pre-publish breakage guard (`--strictPlaygrounds`).** For playgrounds whose imports resolve from the registry, each bare import is checked against the version of the package actually installed in `node_modules` (the version StackBlitz would resolve). An imported entry point or named symbol the pinned version lacks is surfaced at docs-build time: a per-playground warning by default, promoted to a hard build failure under `--strictPlaygrounds`. Both checks (subpath against the `exports` map, symbol against the entry `.d.ts`) are biased toward no false positives; vendored packages and framework peers are exempt.
- **`compodocx playground:validate <docsDir>` subcommand.** Compiles every `@playground` in a generated documentation folder and reports a per-playground pass/fail summary, the strongest guard. It reads the manifests back out of the produced HTML, materializes each StackBlitz project to a temp directory, and runs a real `npm install` + `npm run build`. Opt-in and decoupled from the docs build. Flags `--filter`, `--keep`, `--installCmd`, `--buildCmd`; exit codes `0` all passed / none found, `1` at least one failed, `2` fatal.
- **Custom `<head>` and global styles (`playgroundHead` / `playgroundGlobalStyles`).** `playgroundHead` appends arbitrary `<head>` entries to every generated `index.html` (after the Material shell links, when present) for custom fonts, meta tags, CSP, or preloads. `playgroundGlobalStyles` appends global CSS to every `src/styles.css` after the default body reset. Both extend the same shell writer the Material option uses, so they compose with it rather than replacing the scaffold. Per-block customization remains available through a `block-playground` template override.
- **`@playgroundConfig <relative.ts>` component JSDoc tag.** Ship an `app.config.ts` (providers, `provideRouter`, HTTP interceptors, any application config) into a component's playgrounds. The referenced file is shipped as the project's `src/app/app.config.ts` (its transitive relative imports bundled too) and `src/main.ts` wires `bootstrapApplication(AppComponent, appConfig)`; the file must export `appConfig`. One tag per component applies to all of that component's `@playground` blocks. Replaces the older undocumented `export { appConfig } from './app.config'` trick, which still works for back-compat.
- **`playgroundMaterialShell` config flag.** Forces the StackBlitz shell to emit the Roboto + Material-Icons font links and `mat-typography mat-app-background` body classes even when no `<mat-*>` elements are auto-detected and no Sass theme bridge is present. The shell still emits automatically on `<mat-*>` detection or a Material theme `@use`. The flag and heuristics control only the shell; they do not wire `@angular/material` / `@angular/cdk` deps or a prebuilt theme (those still require real `<mat-*>` usage).
- **Configurable dependency-walk caps (`playgroundDepDepth` / `playgroundFileCountCap` / `playgroundFileCap`).** Config-overridable versions of the built-in StackBlitz caps: max import depth followed when walking a playground's dependency graph (default `3`, range 1–100), hard ceiling on source files in one manifest (default `25`, range 1–1000), and per-file character cap before truncation (default `8000`, range 500–1,000,000). Cap-exceeded errors now name the root, the cap key, and the walked files.
- **Template-literal and computed decorator URLs.** `templateUrl` / `styleUrl` / `styleUrls` written as plain template literals (`` templateUrl: `./x.html` ``) are now resolved like string literals when bundling a `@playground`. Interpolated (`${...}`) or computed values are reported with a clear error instead of being silently dropped into a broken playground.

Migration and tooling foundations. - **`--multiVersion` defaults to `true` (#58).** Output now writes to `<output>/<versionLabel>/` instead of directly to `<output>/`, and a `versions.json` manifest is emitted at the deploy root. The version label auto-resolves from the nearest `package.json`; pass `--versionLabel <string>` to override or to satisfy projects without a `package.json`. Missing label combined with `--multiVersion` is a hard error (exit 2) with a hint pointing at `--versionLabel ... or --no-multiVersion`. See `MIGRATION.md` for the upgrade callout.

### Added

- **`compodocx migrate` sub-command (#53).** Helps existing compodoc consumers port custom Handlebars templates and CSS to the compodocx surface. Four sub-commands: `inspect <path>` reports template-format / CSS-class / config-file drift; `template <file.hbs>` converts a single Handlebars partial to the JS override format (streams to stdout when neither `--out` nor `--dry-run` is set); `templates <hbs-dir> --out <js-dir>` batch-converts a directory; `css <file-or-dir>` rewrites legacy class names to the `cdx-` prefix (conservative by default; `--aggressive` also rewrites HTML / TS / TSX / JS files). Hard limits stop conversion when the input matches a full HTML page, an unknown override name, or any other shape that cannot map cleanly.

- **`compodocx diff` sub-command (#55).** Compares two `--exportFormat json` snapshots and surfaces API changes by severity (breaking, additive, docs-only). Flags: `--old <path>`, `--new <path>`, `--json`, `--md`, `--no-warnings`. Exit codes: 0 clean (no changes), 1 additive only, 2 breaking or fatal error. The default console formatter mirrors `git diff` style with severity-coloured headers; `--json` emits a structured payload for downstream tooling and `--md` emits a markdown report ready to paste into PR descriptions or release notes. Volatile fields (`generatedAt`, `compodocxVersion`) are stripped before comparison so re-runs of the same source produce a clean diff.

Emits a single markdown file (`<output>/llm-context.md`) optimized for LLM context windows: per-entity sections, signal-typed properties, JSDoc tags, and source-file paths. Out-of-range or non-numeric values exit non-zero with a clear error message.

Pagefind unchanged: `await import(/* @vite-ignore */ pagefindUrl)` is a runtime-URL form that bundlers cannot follow, so it is fetched from the deployed site at runtime. `deps.alwaysBundle: [/.*/]` forces every `dependencies` entry to inline; without this override, tsdown's auto-externalization would leave `await import('d3')` as a bare specifier the browser cannot resolve. Bundle size regressed in the project's favour: total client gzipped 110.3 KB → 106.9 KB (-3.1%); entry chunk gzipped 14.5 KB → 13.9 KB (-4.0%). esbuild removed from devDependencies.

### Fixed

- **`@compodoc/ngd-transformer` default-import resolution under Rolldown** (#48). The package flags itself `__esModule: true` but exports no `default`, so `import ngdT from '@compodoc/ngd-transformer'` followed by `new ngdT.DotEngine(...)` resolved to `undefined.DotEngine` at runtime under Rolldown's spec-strict ESM interop (Rollup tolerated this via `@rollup/plugin-typescript` letting TypeScript apply `esModuleInterop` first). Switched `src/app/engines/ngd.engine.ts` to `import { DotEngine } from '@compodoc/ngd-transformer'`. The named import is also more idiomatic TypeScript and works under both bundlers.

- **CLI shebang stripped from `dist/index-cli.{js,mjs}`** (#48). tsdown 0.21.x has a known issue (rolldown/tsdown#886, #300) where it removes the `#!/usr/bin/env node` shebang from CJS and ESM entries. Added `scripts/postbuild-shebang.mjs` as a post-build step that re-prepends the shebang and chmods 0755 on both formats. Idempotent. Without this, direct invocation of the bin would fail on POSIX systems.

- **`scripts/dev-watch.mjs` was broken after the bundler swap** (#50). The dev watcher invoked `npx esbuild` and `npx rollup` directly from its build steps, both of which were removed in #48 / #49. Switched both invocations to `npx tsdown` (root config for the lib step, `tsdown.client.config.ts` for the client step). `npm run dev`, `dev:standalone`, and `dev:module` work again.

### Internal

- **`src/resources/js/compodocx.js` is now a gitignored build artifact** (#50). The file had been tracked since the 0.0.1 initial commit but never updated, and the chunks it referenced (`src/resources/js/chunks/*.js`) were already gitignored, so the committed version always pointed at chunk hashes that don't exist on disk after a fresh clone. Added to `.gitignore`, removed from tracking via `git rm --cached`. The vendored `libs/jszip.min.js` stays tracked. The npm tarball still ships the regenerated bundle because `src/resources/` is in `package.json` `files` and the release workflow runs `npm run build` before `npm pack`.

## [0.0.5] - 2026-05-05

### Fixed

- **Class-level `@example` (and every other class-level JSDoc tag) was silently dropped from generated component / directive pages.** The TSX-era Examples section on the Info tab (and any other render path that reads `c.jsdoctags`) saw an empty array because `component-dep.factory.ts` and `directive-dep.factory.ts` accessed `IO.jsdoctags[0].tags` - a leftover from a 2017-era compodoc shape where `IO.jsdoctags` was wrapped in a single-element array. The TSX migration added a real Examples section but built it on top of the pre-existing broken data path. Both factories now assign `IO.jsdoctags` directly. Verified against a project with 163 `@example` tags: 22 component pages now render an Examples section that previously rendered nothing.

## [0.0.4] - 2026-05-05

## [0.0.3] - 2026-05-05

### Fixed

- **Folder grouping in the sidebar for multi-project Angular workspaces** (`projects/<group>/<lib>/src/...`). The grouping function had a hardcoded marker list that stripped at the first `src/` it found, which collapsed the entire `projects/<group>/<lib>` hierarchy into nothing. ## [0.0.1] - 2026-05-05

First cngx-line tag. compodocx forks compodoc 1.1.32 with the analyzer and configuration story preserved and the rendering layer rewritten from scratch.

### Identity

- Renamed package to `@cngxjs/compodocx` and CLI to `compodocx` (with `compodoc` kept as a binary alias for drop-in compatibility).
- Repository moved to <https://github.com/cngxjs/compodocx>.
- Scope narrowed to Angular only - AngularJS, Angular 1, and TypeScript-without-Angular code paths removed from the analyzer.
- New brand mark, README, and MIGRATION.md.

### Rendering layer (rewritten)

- Migrated all page and block templates from Handlebars to JSX via `@kitajs/html`. The two systems are not compatible at the template level - see `MIGRATION.md` for the cookbook.
- Replaced Bootstrap 4 markup throughout with semantic HTML and CSS Grid / Flexbox layouts. All emitted classes are now `cdx-` prefixed; `data-compodoc="<block-name>"` attributes are also emitted on every section as a stable selector for downstream tooling and CSS.
- Replaced jQuery with native APIs in the client bundle (`src/client/`).
- Replaced Lunr search with [Pagefind](https://pagefind.app/). Search index is generated at build time and works fully offline.
- Replaced the Bootstrap-style theme switcher with a CSS-custom-property-based theme system. Eight bundled themes (`default`, `ocean`, `midnight`, `nord`, `rose-pine`, `ember`, `neon`, `brutalist`) plus a `gitbook` compat theme. Custom themes ship as a single CSS file overriding the design tokens.
- Replaced `prism.js` with [Shiki](https://shiki.matsu.io/) for syntax highlighting. Themes can pair with a Shiki theme via `--shikiTheme`.
- New design system in `src/styles/components/*.css` built on Tailwind v4 utilities + token primitives.

### Modern Angular awareness

- First-class rendering of `inject()`-based DI alongside constructor DI, with a dedicated Dependencies section and modifier badges (`optional`, `skipSelf`, `self`, `host`).
- Recognises and renders `input()`, `output()`, `model()`, `signal()`, `computed()`, `linked-signal()`, and `effect()` constructs distinctly from legacy `@Input()` / `@Output()`.
- Dedicated Derived State section showing `computed()` and `linked-signal()` properties with their `Derives from …` dependency narrative.
- Optional Effects section (`--showEffects`) for documented `effect()` blocks.
- Structured `host` metadata rendered as a flat list of typed entries (static class, static attributes, bound classes, bound styles, events, listeners) instead of a stringified object.
- Standalone-aware: per-component dependency graph for standalone imports, project-level module graph for NgModule projects, automatic detection so the right one shows up.
- New `--publicApiOnly` flag restricts processing to symbols re-exported from a project's public entry.

### Theming tab (new feature)

- New per-component Theming tab driven by inline-doc tokens parsed out of each component's SCSS or CSS.
- Supports CSS custom properties (`--cdx-foo`), SCSS variables (`$cdx-foo`), and `@property --cdx-foo` rules.
- JSDoc / SassDoc tag set: `@overview`, `@type`, `@default`, `@group`, `@example`, `@since`, `@deprecated`, `@see`. `@property` rules' `syntax` and `initial-value` populate `type` and `defaultValue` automatically.
- Configurable via `themingTabSections: ['overview', 'index', 'tokens', 'source']` in the config file.
- Source authoring guide at `docs/theming-tokens-authoring-guide.md`.

### Custom template overrides (new contract)

- `--templates` now expects JavaScript files (CommonJS modules) under `partials/`, replacing the Handlebars partials used by compodoc.
- Each override receives `(data, helpers)` and returns a raw HTML string.
- 27 page-level override names plus 16 block-level override names exposed as a stable contract - see `MIGRATION.md`.
- `helpers` exposes the full export of `src/templates/helpers/index.ts` (i18n `t()`, `linkTypeHtml()`, `parseDescription()`, `codeWrap()`, `functionSignature()`, …) - see `MIGRATION.md` for the full table.
- Reference templates live at `test/fixtures/test-templates/partials/` and are exercised by the CLI integration tests.

### CLI changes

- New flags: `--showEffects`, `--publicApiOnly`, `--disableDependenciesTab`, `--gaID`.
- Removed: `--gaSite` (Universal Analytics is end-of-life - use `--gaID` with a GA4 measurement ID).
- All other compodoc flags retained with identical behavior.
- Help text rewritten where stale (`--templates` no longer says "Handlebars").

### UI redesign

Full visual overhaul:

- New entity hero with breadcrumb, title, badges, file path.
- Member cards reorganised as flat `cdx-io-member` rows for API blocks (`BlockMethod`, `BlockProperty`, `BlockInput`, `BlockOutput`, `BlockAccessors`, `BlockIndexSignatures`, `BlockDerivedState`).
- Sticky source viewer with cloned-line stack and `#L42` deep linking.
- Stripe-style sliding-indicator tab bar on entity pages.
- Dependency graphs (D3 + Graphviz) with zoom-pan controls and fullscreen.
- Overview dashboard with project KPI tiles, dependency graph, and entity inventory chips.
- Coverage report with per-file scores, JSDoc completeness breakdown, and CI thresholds.
- Command palette (`Cmd+K` / `Ctrl+K`).
- Keyboard navigation (`j` / `k`, `[` / `]`, `?`).
- Dark mode by system preference plus manual toggle, with localStorage persistence.
- Eight-theme picker in the topbar.

### Compiler / metadata extraction

- `signalDeps[]` extracted on `computed` / `linked-signal` properties via AST walk.
- `slots[]` extracted from `@slot` JSDoc tags on components.
- `themeTokens[]`, `themeStyleSources[]`, `themeOverview` extracted on components from co-located SCSS / CSS files (one level of `@import` / `@use` followed for SCSS).
- `hostStructured` replaces the stringified `host` object.

- `inject()`-kind properties tracked separately from regular properties for the new Dependencies section.
